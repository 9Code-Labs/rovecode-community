# Past the Ban List: How rovecode Can Say What Good Looks Like

> **Status: historical.** Measured against `src/design/{rules,audit,direction}.ts` at commit f661b70.
> `audit.ts` has since been reworked along these lines — 13 rules, the slop/deviation split, OKLCH hue
> families, page and project scoping — so the counts and the worked failures below describe the code
> *before* the rework, not what ships. For shipped behaviour see [design.md](design.md).

Rovecode's design system today is a negation. `src/design/rules.ts` names eleven things not to do and `src/design/audit.ts` greps for eight of them. The evidence says this is aimed at the wrong layer and fights the model's weakest capability. The single top recommendation: stop widening the ban list and widen what `.rovecode/design.json` RECORDS, then derive the whole visual system deterministically from the one or two values the human actually chose. An unspecified requirement is inferred correctly only 41.1% of the time ([Yang et al.](https://arxiv.org/abs/2505.13360)), so every axis the direction file leaves blank (section order, hero pattern, type scale, density, motion, copy register, contrast pairs) regresses to the training mode on every single call. Fill those axes with human-picked values, derive tokens from the human's seed hex, emit them as a Tailwind v4 `@theme` block so that off-direction utilities do not resolve at all, and collapse every SLOP check in the audit into a DEVIATION check conditional on that record. That respects the hard constraint by construction: rovecode ships budgets, role contracts and derivation functions, never a colour or a face.

## 1. Why models produce slop design

The mechanism is measured, not vibes. Human preference annotators systematically prefer text the base model already finds likely. [Zhang et al.](https://arxiv.org/abs/2510.01171) decompose the learned reward as `r_true + alpha*log pi_ref + eps` and fit alpha on 6,874 HelpSteer pairs matched for identical correctness: 0.57 +/- 0.07 and 0.65 +/- 0.07 against two base models, both p < 1e-14. Under perfect optimisation the policy is the base distribution sharpened by gamma = 1 + alpha/beta. The measured consequence in their creative-writing ablation: Tulu-70B at 45.4% diversity as a base model, 10.8% after alignment.

That typicality is processing fluency, the same quantity that makes prototypical design feel attractive ([Reber, Schwarz and Winkielman](https://pages.ucsd.edu/~pwinkiel/reber-schwarz-winkielman-beauty-PSPR-2004.pdf)). This is the uncomfortable part: slop is not unpopular. In [Design2Code](https://aclanthology.org/2025.naacl-long.199/), human annotators judged GPT-4V's self-revised pages better designed than the real reference websites 64% of the time. So rovecode cannot be sold as "users will like it more." The defensible claim is fit to a chosen direction (opinion, and it should shape the product copy).

Three properties of the collapse are directly actionable. It is cross-provider: LLM creativity-test responses are far more similar to each other than human responses are ([Wenger and Kenett](https://arxiv.org/pdf/2501.19361)), so the model-profile work in this repo will not move design quality either way. It is worst per-input: [Kirk et al.](https://proceedings.iclr.cc/paper_files/paper/2024/file/5a68d05006d5b05dd9463dd9c0219db0-Paper-Conference.pdf) find RLHF's diversity loss is strongest for variation within a single prompt, which means asking one model, once, for "three genuinely different directions" samples one input and gets three near-identical answers. And temperature is not the lever: [Peeperkorn et al.](https://arxiv.org/pdf/2405.00492) find only weak positive correlation between novelty and temperature and moderately negative correlation with coherence.

The prior is genuinely skewed. Per the [Web Almanac 2025 fonts chapter](https://almanac.httparchive.org/en/2025/fonts), Google Fonts has served over 50 trillion all-time views; Roboto leads at ~28 trillion; Inter grew 57% YoY to 414 billion; top desktop request shares are Poppins ~3.8%, Open Sans ~3.3%, Lato ~2.0%, Montserrat ~1.9%. Those are exactly rovecode's banned names. Banning the mode without supplying a replacement forces the model to invent a face with no rationale, which is a different generic (inference).

And the ban list is delivered in the format models handle worst. Negation benchmarks find LLMs insensitive to the presence of negation and unable to reason under it, with explicit negation-aware prompting failing to fix it ([Truong et al.](https://www.alphaxiv.org/abs/2306.08189), [Hossain et al.](https://arxiv.org/pdf/2209.12711), [MIT on VLMs](https://news.mit.edu/2025/study-shows-vision-language-models-cant-handle-negation-words-queries-0514)). "Not amber" primes amber.

## 2. What makes design good, and which parts a machine can hold

| Property | Survives as a machine CHECK | Survives as a generative INSTRUCTION | Taste-only |
| --- | --- | --- | --- |
| Contrast (WCAG ratio) | Yes, if the direction records fg/bg PAIRS | Yes, as a target ratio to solve for | No |
| Contrast (perceived, dark UI) | Yes, via APCA Lc with size and weight as inputs | Yes | No |
| Measure / line length | Yes, when expressed in `ch` (45-80) | Yes, "declare your measure" | No |
| Type scale | Ratio: no. Step COUNT and adjacent-step delta: yes | Yes, "pick N steps and name them" | Which ratio |
| Hierarchy | Only as a lever census (sizes / weights / text colours in play) | Yes, "large OR bold OR dark, not all three" | Which element matters |
| Palette restriction | Yes, as OKLCH hue-family count vs a budget | Yes, "one family plus declared semantics" | Which hue |
| The one unexpected move | No | Only as a required declaration | Yes |
| Spacing consistency | Yes, off-scale utility count | Yes, role-indexed spacing steps | No |
| Line/border density | Yes (already in audit.ts) | Yes, "encode relatedness with space" | No |
| Whitespace fraction / trapped whitespace | Only with rendered geometry | Weak | Partly |
| Section order and hero pattern | Yes, if recorded and named | Yes, choose from a pattern set | Which one fits |
| Motion and background depth | Weak textual check | Yes, as a recorded rule | Yes |
| Optical sizing / variable axes | Yes, "face has axes, none addressed" | Yes | No |
| Concept / organising idea | Only presence of a non-generic rationale string | Yes | Yes |
| Overall aesthetic quality | No | No | Yes |

The through-line: almost nothing survives as a blocklist, but a surprising amount survives as a BUDGET or a COMPLETENESS check computed against the project's own record. A budget contains a number, not a colour, which is exactly what the hard constraint permits.

The measured ones matter most. Converting palette checking from literal hex-set membership to OKLCH hue families collapses AVOID's 23-step token ramp to a single family spanning 1.3 degrees of hue (172.2 to 173.5), and this repo's own `site/src` (34 files, 51 distinct hexes, 28 chromatic) to four families: a dominant navy cluster around 240 and 270 degrees plus semantic red and green. That is what a real human-directed palette looks like, and a family-count budget describes it without naming a colour. Measure is the deepest-backed typographic rule available (Bringhurst's 45-75 with 66 ideal, corroborated by [Baymard](https://baymard.com/blog/line-length-readability)) and `ch` encodes it exactly with no rendering; the site here declares a `ch`-based max-width exactly once in 34 files, and that one is a 16ch label. Type-scale ratio does not survive, because [Utopia](https://utopia.fyi/blog/css-modular-scales/) argues the ratio must differ by viewport (1.2 small, 1.33 large); step count does, and the site has 31 distinct type sizes with adjacent ratios of 1.03 to 1.04, which is sprawl no ban list could name. Hierarchy survives as a census: 31 sizes against 2 weights says hierarchy runs on size alone, and "add a weight step, drop twenty sizes" is the first thing in this whole system that tells the model what to DO.

The ceiling is real. [Reinecke et al.](https://dx.doi.org/10.1145/2470654.2481281) found perceptual complexity plus colourfulness plus demographics explain roughly half the variance in aesthetic ratings, and part of the residual is legitimate cultural difference, not noise. Emit evidence and budgets. Never emit a grade.

## 3. Prior art

**Deterministic derivation from one human seed** is the mature, evidenced layer. Material 3's HCT gives a hard guarantee: a tone delta of 40 implies at least 3.0:1 and 50 implies 4.5:1, turning one input colour into ~65 consistent tokens ([M3](https://m3.material.io/styles/color/dynamic), [material-color-utilities](https://github.com/material-foundation/material-color-utilities/blob/main/concepts/dynamic_color_scheme.md)). Its documented cost is desaturation: the default tonal_spot scheme is low-chroma and users call the result bland. [Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) adds the other half, a semantic role contract per step (3/4/5 component backgrounds, 6/7/8 borders, 9/10 solid, 11/12 text) with steps 11 and 12 guaranteed APCA Lc 60 and Lc 90. [Adobe Leonardo](https://github.com/adobe/leonardo) inverts the problem entirely: specify target contrast ratios, solve for the colours. And [DTCG reached a stable version on 2025-10-28](https://www.w3.org/community/design-tokens/) with [Style Dictionary emitting Tailwind v4 `@theme`](https://github.com/tokens-studio/sd-tailwindv4/), where an `@theme` variable generates the utilities, so `bg-amber-500` simply stops resolving.

**Reference-driven and critic-in-the-loop generation** is evidenced but modest. Text-only self-revision of frontend code is near-worthless and sometimes catastrophic (Design2Code: GPT-4o flat at ~92.7 block-match, DeepSeek-VL-7B collapsing 66.1 to 30.1). A VLM critic on the RENDERED page gives up to +17.8% over three cycles ([arXiv 2604.05839](https://arxiv.org/abs/2604.05839v1)). Independently, [Shin et al.](https://arxiv.org/abs/2603.13036) catalogue web vibe-coding homogenisation and prescribe "productive friction", "contextual anchoring" (ingest real tokens, a brand book, or a live URL) and "style subfloors" (selectable community lineages instead of a default). Style subfloors is the academic name for what the hard constraint demands.

**LLM-as-judge for aesthetics** is the least trustworthy layer. MLLMs rank UIs against human preference decently (Claude Pearson 0.85 on "Interesting", [arXiv 2510.08783](https://arxiv.org/abs/2510.08783)) but absolute scores cluster near the human mean, and judge biases run 10-15 points positional, 15-30 verbosity, 10-25% self-preference. Closing the loop with the same model family is a documented reward-hacking configuration.

**AVOID**, installed on this machine, is the closest working implementation of the positive half. `avoid_brief(product, sector)` returns four things rovecode has none of: named real reference sites with measured section order, hero structure, type scale and real copy; a conventional page outline per sector with allowed patterns per slot; three directions ("ink", "paper", "warm") each with full hexes, a named type pairing WITH a stated reason, a hero pattern, a motion rule and a per-direction avoid list; and copy rules with ~20 banned phrases plus positive requirements (every section carries one number, one product noun or one named customer). `avoid_tokens(hex, vibe)` is the derivation layer above: an OKLCH tinted neutral ramp, brand ramp, semantic light and dark tokens, printed WCAG ratios per pair with pass/fail, a radius language, a shadow recipe, and CSS variables plus a Tailwind v4 `@theme` block. I ran it with a green seed (#2F5D50) and all twelve printed pairs passed. `avoid_references`, `avoid_structure`, `avoid_section`, `avoid_pairings`, `avoid_audit` (0-100 plus grade) and `avoid_rules` round it out. What is marketing: the 0-100 score and letter grade, which the Reinecke ceiling does not support. What is genuinely transferable: measure-first references, per-slot pattern sets, derivation from one seed, and pairings with stated reasons. Caveat worth stating plainly: a curated reference list imports the curator's taste and goes stale, so it must be visible and editable per project, never compiled in.

Adjacent evidence on the ceiling of static checking: [axe-core catches 57%](https://www.deque.com/automated-accessibility-coverage-report/) of accessibility issues across 13,000 pages, and that figure is inflated by colour contrast, the one thing it computes exactly. axe can read a DOM. rovecode's audit cannot.

## 4. Mechanisms we could ship, ranked

**1. Widen what design.json records (cost: low; evidence: [Yang et al.](https://arxiv.org/abs/2505.13360) 41.1% correct inference, 2x regression rate; failure mode: a long interrogation the human abandons; constraint: respected, every field is human-chosen from generated candidates).** Add section order, hero pattern, type scale steps, density, motion rule, background depth, copy register, fg/bg contrast pairs, and a required non-generic rationale. Motion and background depth are where the fingerprint actually lives and `direction.ts` records neither.

**2. Derive the token set from the human's seed and emit `@theme` (cost: medium; evidence: HCT/Radix/Leonardo guarantees, DTCG stable; failure mode: silent desaturation of the human's colour, the Material 3 complaint; constraint: respected, the seed is always the human's).** Preserve chroma as an explicit parameter and let the seed hex survive unmodified as the accent. Prevention against drift into a default: rovecode must refuse to generate tokens when no seed is recorded, rather than falling back to anything.

**3. Verbalized sampling plus varied input anchors at the proposal step (cost: very low; evidence: 1.6-2.1x diversity, training-free; failure mode: three exotic directions the human likes none of; constraint: respected).** Ask for a distribution with typicality labels, and condition each proposal on a DIFFERENT anchor (a different measured reference, a different sector convention, a different seed hex), because per-input collapse is the worse axis. Then enforce the "genuinely different" adjective by measuring hue separation, type-pairing class and layout archetype between the proposals and rejecting a set that is too close.

**4. Rendered critic loop, ranked not scored (cost: high; evidence: +17.8% over three cycles, Visual Score 0.5390 to 0.5584; failure mode: self-bias amplification, [self-refine](https://arxiv.org/pdf/2303.17651); constraint: respected).** Render via the installed playwright / browser-bridge MCP, screenshot at two or three widths, hand the image plus the recorded direction to a critic from a different model family, cap at three cycles, randomise candidate order, and have it shortlist and describe differences rather than decide.

**5. Reference measurement per project (cost: medium, curation is the cost; evidence: Design2Code and WebSight are built on real pages; failure mode: stale, taste-laden lists; constraint: respected if the list is editable per project).**

**6. Do not ship: a temperature knob, an LLM taste score, more bans.** All three are contraindicated by the evidence above.

### The bet

Ship 1 and 2 together, as one thing (opinion). The direction file becomes the complete specification and the generator's output space, not a note. The human picks a seed hex and a face and answers eight short multiple-choice questions built from candidate sets; everything else is derived with contrast guaranteed by construction; the derived tokens become the only utilities that exist in the project. Slop prevention moves from a grep warning to a compile error, and the audit's remaining job shrinks to conformance plus measurable floors. Mechanism 3 is a two-hour add-on that makes the proposal step actually produce three different things, and should ride along.

## 5. Where audit.ts is wrong today

| Check | Problem | What to do |
| --- | --- | --- |
| 1 cliche-accent-amber | Never consults `direction` at all, unlike checks 5 and 6. A chosen amber is permanently unrepealable | Skip any amberish hex within 30 degrees of a palette entry; skip the check entirely when a palette entry is itself amberish |
| 2 cliche-font | Fires on `system-ui` inside a correct fallback stack. Bans the empirical mode with no replacement | Only consider the FIRST family in a comma list; re-scope to "a face appears with no recorded rationale" |
| 3 reflex-hero | Reasonable, but purely negative | Replace with "hero pattern must match the recorded one" |
| 4 rule-line-density | The one check with a positive twin missing | Pair with a spacing-off-scale check; the site here has only 3 arbitrary spacing values, so it would be quiet on good work |
| 5 all-square | Correct shape (has an escape hatch) | Keep; make `corners` required so the hatch is always populated |
| 6 everything-centered | Correct shape | Keep |
| 7 cliche-gradient | Narrow and fine | Keep |
| 8 off-palette | Models a palette as a literal hex set; every real system is a derived ramp. Flags 12 steps of one green ramp | Convert to OKLCH, discard C < 0.03 as neutral, bin into 30-degree families, budget of 1 non-direction family for semantic states |
| (missing) | No type-scale, measure, hierarchy-census, contrast, uniform-grid or variable-axes check | Add as budgets and censuses, evidence severity first |

The #D4A017 collision, with arithmetic. AVOID's "warm" accent is R=212, G=160, B=23. L = (212+23)/2/255 = 46.1%. S = (212-23)/(212+23) = 80.4%. H = 60 * (160-23)/189 = 43.5 degrees. rovecode's `isAmberish` accepts hue 20-55, saturation >= 45, lightness 35-80, so it matches on all three axes. A contrast-verified accent from a purpose-built anti-slop standard is reported as cliche. The same band swallows #B45309 (26.0 / 90.5 / 37.1) and #E8A33D (35.8 / 78.8 / 57.5). Worse, I ran `auditSource()` against the literal CSS from `avoid_tokens(#2F5D50)` with a matching direction recorded, and got cliche-font HIGH on `system-ui` in a fallback stack plus off-palette MED listing twelve steps of the single derived green ramp. A checker with known false positives on correct output gets globally ignored, which `audit.ts`'s own header comment predicts.

### Measured against the shipped checker

Five probes run through `auditSource()` from `src/design/audit.ts` itself, on this checkout. These are measurements, not predictions.

1. **A human-chosen warm direction is reported as slop.** Record `brand #D4A017` in `design.json` with its derived ramp, write that ramp into a token file, and the audit returns `[high] cliche-accent-amber` (7 occurrences) plus `[med] off-palette` naming six colours that ARE the ramp of the chosen brand. Check 1 never reads `direction` at all; check 8 compares by exact hex string, so no tint or shade of the chosen colour can ever count as in-palette. The human followed the protocol exactly and the tool calls the result a cliche, permanently, on every file that carries the brand.
2. **A data table.** Nine border declarations over about 15 elements gives 0.60 and fires `rule-line-density` at med. Borders are how a table separates cells; the check has no notion of element kind.
3. **An auth screen.** `min-h-screen` with an `<h1>` fires `reflex-hero`. A full-height centred sign-in is the correct pattern for that job. It escaped `everything-centered` only because it has 7 elements and the gate is 8 or more, which is luck rather than design.
4. **A terminal or brutalist panel.** 0.48 border density plus `all-square`. Both are the aesthetic. Recording `corners: "sharp"` silences the second; nothing silences the first, because `direction` has no borders or density field to record the intent in.
5. **The canonical slop page scores zero.** A three-column feature grid under a heading, copy reading "all-in-one platform", "empowers teams of all sizes", "unlock the power", "cutting-edge", "game-changing", "supercharge" and "take your productivity to the next level", built with a teal accent, an unlisted face, radius present and no full-viewport hero, returns "No design findings."

Probe 5 is the brief's complaint made concrete: every ban satisfied, nothing good produced. It also shows the prompt and the checker disagreeing with each other. `rules.ts` names "the generic three-column feature grid under a centred heading" and "every fact at the same size in one long column" as defaults to climb out of, and `audit.ts` has no check for either, so the two halves of the system do not cover the same list.

A census of direction-awareness explains most of the false positives above. Four of the eight checks can be told a choice was deliberate: 2 subtracts the chosen faces, 5 reads `corners`, 6 reads `layout`, 8 reads `palette`. The other four (amber, reflex-hero, rule-line-density, cliche-gradient) cannot be overruled by anything except the global `ignore` list, which silences them for the whole project rather than for the case that was chosen. `audit.ts`'s own header states the principle it breaks: "A checker that cannot be told 'this was deliberate' gets ignored, and an ignored checker is worse than none."

The fix is precedence, not threshold-fiddling. Slop is unchosen cliche. The moment a human recorded it, it is a deviation question. Every SLOP check should first consult the direction and demote to a NEEDS-REVIEW severity, borrowing axe-core's "incomplete" discipline.

The uncountable half is real and should be admitted rather than faked. Whitespace has a genuine literature target (~50% white-space fraction, plus trapped white space defined as white space not reachable from the margins, [Harrington et al., DocEng 2004](https://doi.org/10.1145/1030397.1030419)) but these are area computations over laid-out boxes. A spacing-utility-per-element ratio is not a white-space fraction; it is a made-up number. Balance, tension, rhythm and the single organising idea are taste-only. The organising idea survives only as a required, non-generic `rationale` string plus one line in rules.ts asking each new section to state how it serves that rationale, or to declare itself neutral scaffolding.

## 6. What I would build next

Sequenced, smallest first.

1. Two one-line fixes to `src/design/audit.ts`: first-family-only font matching, and the direction escape hatch for check 1. This removes the strongest argument against the whole system and costs an afternoon.
2. Rewrite check 8 in OKLCH with a hue-family budget of 1 plus declared semantics. Highest value per line in the audit.
3. Extend `src/design/direction.ts`: required `rationale` with a generic-word stoplist ("modern, clean, sleek, professional, minimal, bold" as the entire content fails), `pairs` of fg/bg with a role, optional `typeScale: number[]`, optional `typeface.axes`, plus `motion`, `depth`, `density`, `sectionOrder` and `heroPattern`. All human-chosen, all optional-to-omit but recorded when chosen.
4. Add the positive checks in this order: measure-undeclared, hierarchy-levers (informational), type-scale-sprawl (low severity first, since it fires on this repo's own site), spacing-off-scale, uniform-grid, variable-axes-unused.
5. Move the ban list out of the always-on prompt and into the audit only. Replace it in `rules.ts` with positive selections of the same extension: name your face and why, pick a hero pattern from a set, declare your measure.
6. Then and only then, the seed-to-tokens derivation and the `@theme` emission, and a `design_direction` read-back tool so the direction is consulted at build time rather than only written once.
7. Last, opt-in `design_audit --rendered` via the installed browser MCP for white-space fraction and alignment-edge count, plus a pairwise VLM critic that ranks two or three implementations for the human.

What NOT to build: a default theme of any kind; a 0-100 score or letter grade; an LLM taste judge in the loop; a creativity temperature knob, coupled or otherwise, to the thinking-effort dial; a text-only self-revision pass; any "iterate until the score is above N" loop; more entries in the ban list; and any hard dependency on an external MCP without a local fallback (the shadcn server in this environment is currently timing out, which makes the point).
